The reply advises whether a WebSocket handler should extend `RequestHandler`, whose behaviour is built around one
request and its response (parsing and matching a request, running a resolver that returns a response, cloning the
request).

PASS if: It grounds the answer in what the parent class does: a connection-event handler would not use that
request-and-response behaviour, and would have to override it, leave it empty or work around it.
FAIL if the reply does not meet that, or contradicts it.
